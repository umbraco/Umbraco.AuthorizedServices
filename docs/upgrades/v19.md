# Upgrade to Umbraco 19

From `18.0.0` to `19.0.0-rc1` (tag `release-19.0.0-rc1`).
Branch `release/19.0.0`, cut from `origin/main` (`bc260be`), as v17 and v18 were.

**Targets CMS release:** `release-19.0.0-rc1`. While this is a pre-release, the package's own
version is a pre-release too (`19.0.0-rc1`).

## Inventory

What Umbraco 19 changes that this package actually uses. Checked against the CMS diff
`release-18.0.0..release-19.0.0-rc1`, the beta1 and rc1 release notes, and the UmbracoDocs
page `19/umbraco-cms/get-started/upgrading-and-migrating/version-specific.md` (origin/main
`397640cc2c`).

- **.NET 10 → .NET 11, SDK 10.0.100 → 11.0.100** (beta1)\
  Source: `release-19.0.0-rc1:Directory.Build.props`, `release-19.0.0-rc1:global.json`,
  umbraco/Umbraco-CMS#23955 (GA in #24571)\
  Hits: `Directory.Build.props`, `global.json`, all three `.csproj` files. A spike build on
  `net11.0` compiled the package and tests with no errors and no `CS0618`; 49/49 tests pass.
- **`Microsoft.AspNetCore.OpenApi` 10.0.7 → 11.0.0, `Microsoft.OpenApi` 2.0.0 → 3.x
  (transitive)** (beta1)\
  Source: `release-19.0.0-rc1:Directory.Packages.props`, #23955\
  Hits: `Extensions/UmbracoBuilderExtensions.cs` document transformer (sets
  `doc.Info.Version` and `doc.Info.Description`). Compiles unchanged in the spike. The CMS now
  pins OpenAPI 3.1 output, so the regenerated client may differ (see the frontend task).
- **Backoffice uses cookie-based authentication** (beta1)\
  Source: umbraco/Umbraco-CMS#23484; `release-19.0.0-rc1:src/Umbraco.Web.UI.Client/src/packages/core/auth/auth.context.ts:410-425`;
  docs `version-specific.md` "Cookie-based authentication for the backoffice" and
  `19/.../fetching-data/custom-generated-client.md` "Using `configureClient()`"\
  Hits: `Client/src/index.ts:13-17` passes `auth: config?.token` from
  `getOpenApiConfiguration()`. On 19, `token()` returns `undefined` and logs an
  `UmbDeprecation` warning (removal in Umbraco 21). The current code also never binds the
  CMS's response interceptors (401 re-login, problem-details notifications).
  `authContext.configureClient(client)` already exists at `release-18.0.0`
  (`auth.context.ts:663`), so the fix lands on 18 first. Server side needs nothing: every
  backoffice policy, `BackOfficeAccess` included, accepts the cookie scheme at rc1
  (`BackOfficeAuthPolicyBuilderExtensions.cs:200-203`).
- **`@umbraco-cms/backoffice` 18.0.0 → 19.0.0-rc1, peer `@hey-api/openapi-ts` now
  `>=0.99.0 <1.0.0`** (rc1)\
  Source: `npm view @umbraco-cms/backoffice@19.0.0-rc1 peerDependencies` (MyGet prerelease
  feed, already in `Client/.npmrc`)\
  Hits: `Client/package.json` (`^0.97.0` gives `ERESOLVE`). With `^0.99.0`, `tsc --noEmit`
  and `npm run build` pass on 19.0.0-rc1. All 12 import paths, every manifest type, kind and
  meta field, `Umb.Menu.AdvancedSettings`, and every `umb-*`/`uui-*` tag the client uses still
  exist at rc1. UUI stays on major 2 (2.0.0 → 2.2.0).
- **Static web asset compression fails on the test site** (rc1, .NET 11 SDK)\
  Source: spike build, `MSB4018` "Endpoints not found for related asset ...
  umbraco.cms.staticassets/19.0.0-rc1/.../app-auth-callback.element.js". The CMS's own
  template sets `<CompressionEnabled>false</CompressionEnabled>`
  (`release-19.0.0-rc1:templates/UmbracoProject/UmbracoProject.csproj`).\
  Hits: `examples/Umbraco.AuthorizedServices.TestSite/Umbraco.AuthorizedServices.TestSite.csproj`.
  Adding the line fixed the spike build.
- **New `AV0014` analyzer warning (Asp.Versioning 10.2.1): "Add [ApiController]"** (rc1)\
  Source: spike build\
  Hits: `examples/.../Controllers/HubspotContactsController.cs:12`,
  `examples/.../Controllers/TestAuthorizedServicesController.cs:11` (demo site only).

Checked, no hit: 32 `category/breaking` PRs in range (only #23484 and #23955 hit; #24001 and
#24653 are on an unmerged feature branch). Unchanged or changed without touching what the
package uses: `IComposer`, `AddUnique`, `BackOfficeRoute`, `MapToApi`, `AuthorizationPolicies`
(constants added, #23906), `AppCaches`, `IScopeProvider`/`IScope`, `PackageMigrationPlan`,
`AsyncMigrationBase` (#23984 changed `AddColumn`, unused), `IJsonSerializer`, `Attempt`,
`SemVersion`, `GlobalSettings`. No `TODO (V19)` marker touches the package. No V19 data
migration touches the package's tables or `umbracoKeyValue`. `/umbraco/api/AuthorizedServiceResponse`
callback routes are unaffected. No `CS0618` on 18.0.0 or 19.0.0-rc1; no `@deprecated` lint hits
on 18.0.0.

## Third-party dependencies

This release is a package major (version-aligned), so shipped dependencies were reviewed.

- **Microsoft.CodeAnalysis** 4.13.0 → remove. Picked.\
  Breaks: nothing in the package uses it. It ships to every site and pins
  `Microsoft.CodeAnalysis.CSharp.Workspaces` at 4.13.0, while CMS 19 brings
  `Microsoft.CodeAnalysis.CSharp` 5.9.0 through `Umbraco.Cms.DevelopmentMode.Backoffice`
  (in-memory models). Also referenced by the demo site.
- **@hey-api/openapi-ts** ^0.97.0 → ^0.99.0. **Forced** (backoffice peer); goes in the
  frontend bump task. Dev-only.

No third-party code is bundled into the client (the generated API client is the package's own
code), so there's nothing else shipped on the npm side.

## Breaking changes for consumers

- Requires .NET 11 and Umbraco 19.
- The package no longer brings in `Microsoft.CodeAnalysis` 4.13.0 (and the Roslyn packages
  under it). A site that relied on getting Roslyn through this package must reference it
  itself.
